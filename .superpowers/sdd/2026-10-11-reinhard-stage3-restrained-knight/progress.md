## Rulings

- Ruling: one commit per plan task (user rule) instead of the plan's two commits in Tasks 1 and 8 (`feat(client): hit-stop helper`, `feat(hero): safe spot search`); the commit message names both parts — cost if wrong: history granularity only.
- Ruling: the snapshot carries the action phase (combo hit, catch/reflect snap, throw) in the generic `variant` field and the target in `controlTargetId`; `actionBusy` = a timeline runs — the plan names only `actionId/actionElapsed/actionLength/controlTargetId` — cost if wrong: one more int on the wire. Side effect: `SuperJumpClient.anchored` reads an own `controlTargetId >= 0` as "anchored", so Reinhard cannot super-jump / air-step while a targeted action (sky kick, grab hold, dash behind) runs.
- Ruling: `ReinhardHero.canAct` answers true for every ability action while alive and not anchored; the ability gate (control, mode, cooldown, busy, running timeline) is `ReinhardActions.gate` — cost if wrong: none (HeroInputC2SPacket never asked canAct for hero slots).
- Ruling: a controlled Reinhard (dead or anchored by FREEZE/STASIS) drops every running action each tick (`ReinhardActions.tick`), a mode switch and every cleanup / dimension change do the same — cost if wrong: an action a PULL-grabbed Reinhard started keeps running (PULL does not deny actions in `ControlManager`).
- Ruling: clip names are constants in the hand-written `client/reinhard/ReinhardClips` (not generated by the script); `ReinhardClipsTest` (Task 11) checks every name exists in the animation file the script writes — cost if wrong: none, the test catches drift.
- Ruling: `HitStop` holds a hero clip by subtracting the ticks spent in the stop (`heldTicks`) and holds a target in place by translating it back to its interpolated position at the trigger (`RenderLivingEvent.Pre/Post`); the pure core also gives the plan's `frozenPartial` — cost if wrong: feel only.
- Ruling: Light Punch's hit goes through a shared `ability/Strikes` (`hit` = i-frames skipped and restored on a miss, `knockback` = vanilla `LivingEntity.knockback` after a landed hit when `allowsImpulse`, `hurtMarked` set) — later abilities reuse it — cost if wrong: knockback resistance scales Reinhard's push like any vanilla knockback.
- Ruling: the first-person action pose is a pure table `client/reinhard/ReinhardFirstPersonPose` (pose-stack offset + extra arm rotation on the main arm, mirrored for a left main arm), timed like the third-person overlay (elapsed + partial − hit-stop) — cost if wrong: feel only.
- Ruling: the 16×16 ability icons are drawn by `make_reinhard_icons.py` (house pixel style, white plate = Restrained, blue = Knight); `--assets` became optional (the copied archive files are skipped without it) — cost if wrong: art only.
- Ruling: an accepted Step Dash does NOT send the velocity back (`hurtMarked` stays false; the server keeps a copy), unlike the plan's "`hurtMarked = true`": the client already moved, and a motion packet arriving after the 4 predicted ticks (ping > 200 ms) would kick the player a second time; this is the stage 2 air-step precedent (`HeroAirJump`: "server copy only") — cost if wrong: if only the server's gate passes (desync the other way) the cooldown is spent without a dash. A refusal sends `ClientboundSetEntityMotionPacket` with the server's velocity (plan) through a new default `AbilityHandler.refused` hook the router calls after the refuse sound.
- Ruling: the server's velocity copy follows the look (the server has no movement input for a player); the client predictor uses WASD (`input.forwardImpulse/leftImpulse`, vanilla `moveRelative` rotation) — cost if wrong: none for movement (the client is authoritative for its own position), only the server-side copy differs.
- Ruling: friction in `velocity(distance, ticks, friction)` is the real one under the player (block slipperiness × 0.91, air 0.91), so the dash covers ~6 blocks on ice and in the air too; the client stops re-applying on `horizontalCollision` or when the speed drops under 25 % of the set speed (wall, server stop) — cost if wrong: feel only.
- Ruling: "afterimage pixels" = six vanilla `POOF` particles along the first blocks of the path, sent by the server (everyone sees them), next to `HeroFx.launch` — cost if wrong: art only.
- Ruling: the catch window is its own counter (`ReinhardState.catchWindow`, flag `CATCH_WINDOW`), separate from the action timeline: a catch restarts the timeline in phase `ActionTimeline.PHASE_SNAP` for max(window left, `CATCH_SNAP_TICKS` = 6) so the closing hand always plays, while the window still closes 10 t after the press — cost if wrong: after a late catch the action lock outlasts the window by ≤ 6 t.
- Ruling: the catch's FX and sound run inside `ReinhardHero.projectileResponse` when it answers CATCH (`HeroProjectiles` applies it right after) — no new shared hook; the shared catch keeps its own pickup sound (1.4), Reinhard's `reinhard.catch` (= `entity.item.pickup`, pitch 0.8) plays on top — cost if wrong: two layered pickup sounds.
- Ruling: the catch takes projectiles from any direction (the plan names no cone; Arrow Protection deflects from every side too) — cost if wrong: a catch "behind the back" is possible.
- Ruling: a Fist Combo press during a running hit is queued (`AbilityHandler.claimsPress`) and starts the next hit when the current one ends, instead of the gate's refusal sound for every early press — cost if wrong: mashing gives a steady chain instead of dropped presses.
- Ruling: the combo's pushes are not in the spec: 0.4 / 0.4 / 1.0 along the look, wave 0.8 outward (`ReinhardRules.COMBO_KNOCKBACK`, `COMBO_WAVE_KNOCKBACK`) — cost if wrong: balance only.
- Ruling: the third hit's wave hits around the punched target (or the reach point on a miss), skips the punched target (it took the 16), and its eruption throws blocks only (`HeroDebris.erupt` with 0 damage and every entity spared), so the living take damage only through `ReinhardTargets.canHit` + `Strikes` — cost if wrong: none for blocks; entities standing on the torn ground are not tossed by the eruption itself.
- Ruling: "chain broken by a hit-stop" = any other action's timeline (Sky Kick / throw carry the hit-stop) resets the chain in `FistCombo.tickChain`; a mode switch / control / cleanup resets it through the router — cost if wrong: none.
- Ruling: `HeroFxS2CPacket` got three shared kinds — `HIT_STOP` (6, entity ids as {hi16, lo16, 0} triples via pure `HeroFx.encodeIds/decodeIds`, ticks in `power`), `SONIC_RING` (7), `AIR_TRAIL` (8) — drawn by the new shared `client/render/vfx/AirTrailVfx` (ring radius and the 40 t trail length are client constants, the packet carries only the point / ids) — cost if wrong: a packet version bump for old clients (same mod jar on both sides, so none in practice).
- Ruling: the Sky Kick toss is straight up (horizontal velocity zeroed; the server's copy of a player's velocity is stale), the hit-stop holds the target by re-sending zero velocity each held tick (players get the motion packet at once), and a kick that misses (target drifted > reach + 2 + width away during the toss, or `hurt` returned false) ends the action without a launch; the cooldown stays spent — cost if wrong: a dodged kick still costs 10 s.

- Ruling: the grab keeps the `ControlManager` of the level where it was acquired, so a Reinhard dimension change still releases the PULL in the right manager — cost if wrong: none.
- Ruling: "control on Reinhard" during the hold includes PULL (`isControlled`); FREEZE / STASIS already cancel every action through the router — cost if wrong: a PULL by anyone ends his grab.
- Ruling: reaching `GRAB_MAX_TICKS` (100) throws automatically (the plan's "Press 2 (or GRAB_MAX_TICKS)"); forced ends (death / logout / dimension / hero / mode change / control / target lost, dead or > 8 blocks away, or its effect id replaced) release with no throw and still start the cooldown — cost if wrong: the cooldown is spent on a forced end.
- Ruling: the throw launches only when its 15-damage hit landed (the impulse rule), otherwise the action ends with the cooldown spent; the re-applied velocity (`THROW_SUSTAIN_TICKS`) stops on a block collision (from the 2nd sustained tick) or a lost impulse, and a mode change / cleanup stops it too — cost if wrong: feel only.
- Ruling: the hold point (hand at 1.35, target hanging 0.85 of its height below it, at least 0.3 above Reinhard's feet, 0.7 + half its width ahead) is not collision-checked, like the Hulkbuster grab — cost if wrong: a held mob may clip into a wall during the hold.
- Ruling: `THROW_SUSTAIN_TICKS` = 21 from `GrabThrow.sustainTicks(120, 3.9·cos 12°, 0.91)` (no gravity in that formula; the test simulates vanilla drag + gravity from 1 block up and gets ~116 blocks) — cost if wrong: one constant.

- Ruling: the Dash Behind request rides in `ReinhardState.behindRequest` only while `ReinhardActions.handleDashBehind` runs the shared gate and `tryStart`; a `HeroInputC2SPacket` for DASH_BEHIND (only a modified client sends one: the slot is out of `heroInputSlots`) finds no request and is refused with the sound — cost if wrong: none.
- Ruling: every key edge sends one packet, even with nothing under the crosshair (target id −1 → the refusal sound, like any refused press); a packet from a non-Reinhard player or for a slot not on the active page is dropped silently (as `HeroInputC2SPacket` does), the vanilla movement check then puts a predicted client back — cost if wrong: no refusal sound in those two cases.
- Ruling: a valid target is any alive living entity that is not him and not a spectator, allies and creative players included (it is a movement, not a hit; `ReinhardTargets.canHit` is not applied), within 24 + 2 blocks of the server's position — cost if wrong: he can dash behind a friend.
- Ruling: "behind" uses the target's `getYRot()` (body yaw for mobs, the look yaw for players); he lands facing the target's mid-height. The search grid is 0.5 blocks within the 3-block sphere, nearest first, ties with the smaller vertical offset first; a spot may hang up to 6 blocks above ground (he falls), never over the void — cost if wrong: feel only.
- Ruling: the new packet is registered last in `CoreMessages`, so the ids of the existing packets do not change — cost if wrong: none.
