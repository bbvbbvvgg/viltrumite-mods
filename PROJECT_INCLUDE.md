# PROJECT INCLUDE

Этот файл — короткий постоянный мета-контекст проекта для новых сессий и агентов.

Если пользователь пишет `PROJECT_INCLUDE`, `project include` или «прожект инклудий», прочитай этот файл и считай нижеописанный контекст активным для текущей сессии. Не заставляй пользователя заново пересказывать эту историю.

## Контекст про друга и соревнование

У пользователя есть друг, который параллельно делает собственный **rebirth / переосмысление другого мода**. Между проектом пользователя и проектом друга идёт дружеское соревнование: кто сделает мод интереснее, насыщеннее и круче по механикам.

Это не формальный конкурс с жёсткими правилами. Скорее постоянное взаимное сравнение проектов, идей, героев и механик.

Друг просил пользователя:

- добавлять **побольше героев**;
- по возможности делать новых героев **не настолько запредельно сильными**, чтобы весь рост проекта не сводился только к персонажам уровня Рейнхарда и другим ультимативным героям;
- расширять ростер за счёт более разных по масштабу и геймплею персонажей.

Сам друг в своём rebirth-проекте, насколько известно пользователю, делает **какие-то интересные механики и игровые системы**, поэтому при сравнении проектов важны не только количество героев или их сила, но и оригинальность механик, глубина управления и общий игровой интерес.

## Как учитывать этот контекст

Когда обсуждаются следующие герои, новые системы или направление развития Viltrumite Mods:

- помни, что пользователь хочет сохранять конкурентный темп относительно проекта друга;
- количество качественных героев действительно имеет значение;
- не нужно автоматически делать каждого следующего героя сильнее предыдущего;
- хороший кандидат может быть слабее топовых героев, если у него интересное управление, уникальные механики и достаточно глубины;
- при выборе между «ещё один сверхсильный герой» и «менее сильный, но очень самобытный герой» второй вариант часто лучше соответствует текущему направлению проекта;
- не превращай это в искусственное ограничение баланса: если конкретный персонаж по канону должен быть очень сильным, его не надо специально ослаблять только ради соревнования.

Главная идея: **проект должен выигрывать не только мощью отдельных героев, а шириной ростера, качеством реализации и интересными механиками.**
