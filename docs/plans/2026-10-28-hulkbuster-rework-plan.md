# План реализации: Халкбастер Mark 48, полная переработка

> Дата: 2026-10-28. Спек: `docs/design/2026-10-28-hulkbuster-rework.md` (утверждён). Ветка `feat/hulkbuster-rework`, PR #68 → `feat/thor-r3-world`.
> План не меняет решений спека. Решения «как», которых нет в спеке, отмечены **[решение]**.

## 0. Порядок этапов
H1 → H2 → H4 → H3 → H5 → H6 (спек §13; H4 раньше H3: надевание использует те же правила свободного места и посадки, что и приземление/пике).
Приоритет при нехватке сил (из задачи владельца): квадраты на груди + риг + клипы walk/idle/комбо → надевание → захват ПКМ → перемещение (рывок, реактивный прыжок, пике) → ульта → звук → остальные способности. Недоделанное документируется, а не подключается наполовину.

## 1. H1 — риг, модель, квадраты, FP-руки, масштаб и хитбокс
**Квадраты на груди.** Корень найден до кода: glow-текстура `hulkbuster_glow.png` содержит 6 светящихся пикселей внутри UV верхних грудных пластин `cube_17`/`cube_21` (зеркальная пара, грани `up`/`west`, после поворота 69° смотрят вперёд). Проход `RenderType.eyes` рисует их полной яркостью аддитивно → два белых квадрата у внешних верхних углов груди. **[решение]** glow-маска собирается скриптом из белого списка излучающих деталей (визор, реактор, ладони, стопные и спинные двигатели), всё остальное в маске чёрное; тест сверяет маску с UV каждого куба.

**Риг** — `tools/assets/rig_hulkbuster.py` (воспроизводимый, читает неизменённый Sind-источник `tools/assets/hulkbuster_src/`):
- `root → pelvis → torso → chest → head (+ visor)`; `chest → shoulder_{r,l} → upper_arm → forearm → hand → fingers, thumb`; `pelvis → thigh → shin → foot → foot_thruster`; `chest → back_thrusters, reactor, chest_flap_{l,r}, back_flap`; правое предплечье — отбойник (Sind-рука отбойника зеркалится на правую сторону, поршень `piston_r`).
- Кисти разрезаются по оси (box UV → явные UV граней): ладонь / пальцы / большой палец; пивоты в суставах.
- Безымянные `cube_N` раскладываются по костям по положению (таз/живот/грудь).
- Отдельный FP-файл рук из того же рига (`mark48_fp.geo.json`).
**Масштаб**: Sind 68 px × 32/68 × 1.7 = 3.4 блока (как сейчас). **Хитбокс**: 1.3 × 3.2 — **[решение]** аддитивный шов `HeroDefinition.bodyWidthScale` (по умолчанию = `bodyScale`), `HeroSizeEvents` масштабирует ширину и высоту раздельно; остальные герои не меняются.
**Рендер** (`HulkbusterRenderer`): владеет всем, что рисовала ваниль (ник, невидимость, свечение-контур, shadow pass, предмет в руке), FP и TP на одних часах (`ActionClock.sample`), позы только из клипов (`HulkbusterPoses` с числами удаляется), ограниченный поворот корпуса.
**Тесты**: парсинг гео/клипов, glow-маска только на белом списке, иерархия рига (имена/родители), хитбокс-размеры, «рост только при свободном месте».

## 2. H2 — клипы, тайминги, резолвер, кит
- `hero/ironman/hulkbuster/HulkMove` (enum, `StagedMove`): каждая строка = длины фаз, приоритет (1 утилита … 6 ульта), окно отмены, гиперброня `resists`. Длины = клипы (тест).
- `HulkStrikes` — одна строка данных на удар: клип, тик контакта, дальность/конус, урон, отброс, хит-стоп, тряска, VFX, звук, FP-строка.
- `HulkbusterControls` — единственный резолвер (сервер, клиентский перехват мыши, серые слоты): контекст → приём.
- `HulkbusterCombat` — сервер: `StagedTimeline<HulkMove>`, буфер одного нажатия, отказ = текст HUD + звук.
- Захват (§6.2) на `ControlManager` PULL + `heldTargetId/heldTargetPosition` (общий механизм удержания), шкала вырыва, освобождение при любом конце, кулдаун.
- Клипы — `tools/assets/make_hulkbuster_clips.py` (уроки Рейнхарда: ноги и корпус первыми, easeIn в контакт, easeOut из него, восстановление в живую базу), старые клипы удаляются. Превью: `tools/preview_hulkbuster.py` (контакт-листы спереди/сбоку/сзади).
- Снапшот **[решение]**: пока Халкбастер активен, `actionId = 1000 + wireId` приёма, `actionElapsed/Length` — шаг, `controlTargetId` — жертва захвата; блок Халкбастера в `extraCooldowns[9..]` (`HulkbusterWire`: фаза/шаг, движение, стадия повреждений, кулдауны). Новых пакетов снапшота нет; тест encode/decode через продакшн-композер.

## 3. H4 — перемещение (§5)
- `HulkbusterMotion` (чистые правила + состояние): разгон/торможение (атрибут скорости), таран на спринте, рывок двойным WASD (2 заряда, завод 6 т), прыжок тап/удержание, реактивный прыжок (заряд до 30 т), висение (до 30 т, один рывок), пике (урон/радиус от высоты), приземление (кратер с >6 блоков). Правило доступности рывка — одна функция для обеих сторон.
- Клиент предсказывает свой импульс (как рывок Тора), сервер проверяет и при отказе возвращает позицию. **[решение]** Новые пакеты `HulkbusterMotionC2SPacket` / `HulkbusterMotionS2CPacket` → протокол **"12"**, core **1.50.0** (единожды, в конце H4).
- Разрушение мягких блоков только через `CarveJobs` с бюджетом и проверкой gamerule `mobGriefing`.

## 4. H3 — надевание, выход, развал, запасная рука
- Сцена надевания в полном масштабе: капсула Вероники, раскрытый каркас Mark 48 (кости створок), закрытие по очереди (ноги → торс → руки → плечи → шлем), посадка. Воздух/земля по наличию места над головой. Скрипт траектории — чистая функция, сервер правит отклонение > 1 блока.
- `parts.geo.json` и `HulkbusterDocking` удаляются. Хитбокс растёт на закрытии торса (проверка реального бокса).
- Прерывание до торса — без кулдауна; после — гиперброня до конца сцены. Камера — существующая аренда/shake + конфиг `cinematicCamera` (по умолчанию вкл.).

## 5. H5 — VFX и стадии повреждений
Только `HeroFx`/`HeroImpactFx`/`PixelVfx`/`CameraShake`/`FlashOverlay`. Стадия 0/1/2 в снапшоте; скрытие пластин костями, искры, дым, мигание реактора.

## 6. H6 — звук
Cue-лист по таймингам H2 (`docs/plans/...-hulkbuster-cues.md`), CC0 через `openverse_sfx.py`, семейства скриптом `tools/sfx/hulkbuster.py`, источники в `tools/assets/ironman_sources.md` + `CREDITS.md`, mono OGG `.ogg.b64`, субтитры во всех 11 локалях, клиентские лупы с явной остановкой, фасад `HulkbusterSounds`. Прослушать звук агент не может — это пишется в PR.

## 7. Dev-команды
`/hulkbuster` (оператор): `suit`, `move <id>`, `damage <0..2>`, `durability <n>`, `cooldowns reset` — один корень.

## 8. Риски
- Нет нативного прогона клиента в песочнице (arm64, llvmpipe) — визуальная приёмка только у владельца.
- Сетевое предсказание рывка/прыжка — проверка только в игре.
- Кисть Sind-модели — один блок; пальцы — разрез блока, а не новая геометрия.
- `RegulusVisualContractTest` падает на arm64 (нет natives) — известная проблема окружения.
