# Сессия 02 — Автоматический плейтест-стенд

> Сначала прочитай `00_RULES.md` — он обязателен. Здесь только твоя задача.

- **Ветка:** `wave1/02-playtest-rig`
- **PR:** `[2.0·02] Плейтест-стенд: сервер и два клиента одной командой` → `integration/viltrumite-2.0`
- **Зона:** `tools/playtest/`, `docs/playtest/`, dev-команды за явным флагом (в обычной игре выключены).
- **Не трогай:** игровую логику и `build.yml`.

## Для игрока
Игрок стенд не видит, но благодаря ему каждая версия проверяется в настоящем Minecraft быстрее и честнее: меньше багов в сборке, которую владелец с другом запускают вечером.

## Обязательно
1. Одна команда: сборка → `runServer` (offline-mode) → два клиента с разными никами, каждый в своём Xvfb → автоподключение к серверу (quick play или аргументы запуска 1.20.1) → сбор логов.
2. Сценарии в data-формате (YAML или JSON): консольные команды сервера, ожидания, удержание клавиш через `xdotool` (не короче 120 мс), скриншоты, проверки по строкам логов, таймауты.
3. Готовые сценарии: smoke всех 14 героев (выбор героя и каждое действие), полный цикл каждого мирового события, город — разрушение и `/city reset` на Atheria (скачивание по `AGENTS.md` §12 в run-директорию, никогда не коммитить).
4. Метрики: TPS/MSPT сервера, FPS и frametime клиентов, память. Отчёт markdown со скриншотами — в ветку `evidence/wave1-02`.
5. `docs/playtest/rig.md` — «плейтест за 10 минут» для любой сессии; файл памяти `.memory-bank/wave1-02-playtest-rig.md`.
6. Прогони полный smoke на текущей базе и опубликуй базовый отчёт в PR: что сломано и где тормозит. Чужие баги не чини — перечисли; исключение — тривиальные блокеры запуска (отдельными коммитами).
7. **Ранняя публикация:** рабочая версия стенда — в первые 2 часа. Другие сессии будут копировать скрипты из твоей ветки.

## Если останется время
- Видео через `ffmpeg -f x11grab`; сравнение скриншотов; GameTest-проверки событий; отдельный workflow с ручным запуском стенда.
