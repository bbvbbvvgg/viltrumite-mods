# viltrumite 2.0 · Волна 1 · Офлайн-окружение и GitHub

Этот файл важнее любых противоречащих ему мест в 00_RULES.md. Выполни его первым, до работы над задачей.

**Не коммить в репозиторий ссылки и идентификаторы Google Drive** (репозиторий публичный, в наборе лежат файлы Minecraft).

## 0. Что у тебя есть
- Своя машина Linux x86_64 **без интернета**. Сеть наружу не нужна и не появится: не пытайся качать Gradle, Maven или ресурсы Mojang.
- **Коннектор Google Drive** (только чтение, не больше 100 МБ за файл) — через него приходит офлайн-набор.
- **Коннектор GitHub (MCP)** — единственный канал к репозиторию: ветки, файлы, PR, комментарии, статус CI. `git push` не работает (нет сети, а сам `git` в набор не входит).

## 1. Скачай и распакуй набор
- Папка на Drive: «Viltrumite offline kit - fixed client». Найди её через коннектор Drive поиском папки по точному имени. Папки «Viltrumite offline kit with client - main» и «Viltrumite offline build kit - main» — старые, их не трогай.
- В ней **16 частей** `ffkit.7z.001` … `ffkit.7z.016` и `SHA256SUMS.txt`. Других частей с похожими именами (из старых папок) не бери и не смешивай.
- Скачай все 17 файлов в одну папку, например `~/dl`, через коннектор Drive (список файлов папки → загрузка каждого файла → перенос на машину).
- Проверь и распакуй:
  ```
  cd ~/dl && sha256sum -c SHA256SUMS.txt     # все 16 строк — OK
  7z x ffkit.7z.001 -o$HOME                 # получится ~/kit (около 2,1 ГБ)
  ```
  Если какая-то часть не OK — скачай её заново. Символических ссылок в архиве нет, обычного `7z x` достаточно.

## 2. Что внутри `~/kit`
- `project/` — репозиторий `bbvbbvvgg/viltrumite-mods` на коммите `main@bc758de` (с папкой `.git`). **Это твоя рабочая копия.**
- `jdk/` — Java 17 (Temurin), `gradle-home/` — Gradle 8.8 и весь кэш Forge 47.3.0 / Minecraft 1.20.1.
- `client-runtime/`, `tools/` — Xvfb, Mesa llvmpipe, xdotool, программа скриншотов.
- `run.sh` — Gradle офлайн с нужными Java и кэшем. `client.sh`, `screen.sh`, `input.sh` — клиент без экрана. Подробности — `README.txt`, `CLIENT.txt`, `MANIFEST.txt`.

## 3. Сборка, сервер, клиент
```
cd ~/kit
./run.sh                                        # = ./gradlew --offline build (с тестами)
./run.sh :viltrumitecore:runServer > server.log 2>&1 &   # dedicated server
./client.sh > client.log 2>&1 &                 # Xvfb + Mesa + Forge dev-клиент, экран 1280x720
./screen.sh /tmp/shot.png                       # скриншот
./input.sh mousemove 640 565 click 1            # мышь
./input.sh key Escape                           # клавиши; удержание: keydown W; sleep 0.5; keyup W
```
- Вместо `./gradlew …` из 00_RULES.md всегда вызывай `~/kit/run.sh …` (аргументы те же).
- Долгие процессы (сервер, клиент) — только в фоне с логом. Ход загрузки смотри через `tail -n 50 client.log`, не через `tail -f`.
- При первом старте клиента нажми «Continue» на экране специальных возможностей.
- После аварийного завершения клиента удали `~/kit/.client-session`, иначе он не стартует.
- Сервер: в `project/run/server.properties` поставь `online-mode=false` и прими EULA (`eula=true` в `project/run/eula.txt`) — это локальная проверка, файлы `run/` не коммить.
- **Память.** Машина может быть всего 2 ядра и 4 ГБ. Не запускай сборку параллельно с клиентом. Перед запуском смотри `free -m`. Порядок для теста: собрал → остановил всё → сервер → клиент.
- **Два клиента.** `client.sh` держит одну сессию на папку набора. Второй клиент — только если свободно ≥ 6 ГБ: скопируй набор (`cp -r ~/kit ~/kit2`) и запусти `~/kit2/client.sh`. Если памяти не хватает — сервер + один клиент, а мультиплеер с двумя клиентами пометь в PR «НЕ ПРОВЕРЕНО В ИГРЕ: не хватило памяти машины».
- Рендер программный на CPU: FPS низкий, картинка не эталонная, звук выключен (`ALSOFT_DRIVERS=null`). Звуки проверяй по логам и событиям, честно пиши, что не слышал их.
- Мир Atheria для теста города: на Drive файл `Atheria_v2.06_Viltrumite_Ready.zip` (найди по имени). Если коннектор не отдаёт его из-за лимита 100 МБ — тестируй на сгенерированном городе и пометь это в PR. Мир не коммить.

## 4. GitHub только через MCP — экономно
Лимиты GitHub API общие на все 30 сессий (около 80 созданий контента в минуту на всех). Перерасход = 429 у всех.
- **Читай и ищи код локально** в `~/kit/project` (`rg`, `grep`, `find`). Не используй `get_file_contents` и `search_code` для того, что уже есть локально.
- **Старт.** `create_branch` → `wave1/NN-<slug>` от `integration/viltrumite-2.0` (если ветка уже есть — это перезапуск: возьми её последние коммиты через `list_commits` и сначала подтяни изменённые файлы). Локальная копия — это `main@bc758de`; `integration` отличается от неё только настройкой CI в `.github/workflows/`, её не трогай и не перезаписывай.
- **Учёт изменений без git.** Сразу после распаковки сними отпечаток проекта, после каждого пуша — новый:
  ```
  cd ~/kit/project
  snap() { find . -type f -not -path './.git/*' -not -path './build/*' -not -path '*/build/*' -not -path './run/*' -not -path './.gradle/*' -print0 | sort -z | xargs -0 sha256sum; }
  snap > ~/pushed.sha                                  # после распаковки и после каждого успешного пуша
  snap > ~/now.sha; diff ~/pushed.sha ~/now.sha | grep '^[<>]' | awk '{print $3}' | sort -u   # что изменилось
  ```
  Если на машине всё же есть `git` — можно `git status` и `git diff --name-only` в `project/` (только локально, без push).
- **Чекпоинт каждые 10 минут** (а не 5 — из-за общих лимитов): **один** `push_files` в свою ветку со всеми изменёнными файлами, не больше ~30 файлов за раз. Удалённые файлы — `delete_file`. Затем проверь `list_commits` по своей ветке: верхний коммит твой. Сообщение — conventional на английском, промежуточные с `[skip ci]`.
- Бинарники (png, ogg, модели) — только base64 в `viltrumitecore/src/main/binassets/<путь>.b64` (правило репозитория). Сборка у тебя локально должна быть зелёной до пуша без `[skip ci]`.
- **PR** — `create_pull_request` черновиком в `integration/viltrumite-2.0` сразу после первого пуша. Комментарии оркестратора — `pull_request_read`, не чаще раза в 10 минут.
- **CI** — статус проверяй не чаще раза в 10 минут. CI собирает ту же ветку с интернетом; если локально зелено, а в CI красно — разбирайся по логу.
- **На 429 или «rate limit»:** жди retry-after (не меньше 60 с), потом с нарастающей паузой. Не повторяй запрос в цикле. Чтобы ничего не потерять, работа всё равно лежит локально — просто отправь её следующим чекпоинтом.
- **Доказательства** плейтеста (скриншоты, выдержки логов) — в ветку `evidence/wave1-NN` через `push_files`, скриншоты base64 или ужатые до ~300 КБ; не больше 15 файлов за всю сессию. Ссылки на них — в PR.

## 5. Если что-то не работает
- Не спрашивай владельца. Запиши проблему в PR («Состояние и следующий шаг» и раздел «Ограничения») с точным текстом ошибки и продолжай то, что можно сделать.
- Нехватка памяти, падение Xvfb, отсутствие `7z`, отказ коннектора — это блокер окружения: опиши, обойди (меньше памяти Gradle, без второго клиента), не выдавай непроверенное за проверенное.
