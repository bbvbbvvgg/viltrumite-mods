## 5. Архитектурные решения (обязательны для интеграции)
- **D1. Версии и протокол.** Номера версий и `PROTOCOL_VERSION` в ветках воркеров будут конфликтовать — это не дефект PR. Итоговые номера назначает оркестратор при интеграции: каждая значимая интеграция — следующий minor core (flight — если менялся), любое изменение пакетов — протокол +1. Финальный PR поднимает core до `2.0.0`; flight — по факту изменений.
- **D2. Сохраняемые перечисления.** `HeroId`, `HeroAction` и другие сохраняемые enum — только дописывать в конец. Без переименований, удалений и перестановок: на них завязаны сохранения миров. При конфликте порядок определяется порядком интеграции.
- **D3. Пакеты.** Новые регистрации в `CoreMessages` — только в конец. Порядок закрепляет `HeroRosterIntegrationTest`: тест обновляется в том же PR.
- **D4. Маска действий.** Новые действия неизбежно получат ordinal ≥ 64. Расширение маски (`long[]` или `BitSet` + сериализация + протокол) делает **одна** выделенная работа, конкурирующие правки отклоняются. До неё новые герои не могут полагаться на частичную маску доступности.
- **D5. Граница героя.** Поведение героя — только через `HeroDefinition`, без ветвлений по `HeroId` (`NoHeroBranchTest`). Анимации — только существующей системой (AGENTS.md §3); новые анимационные системы запрещены.
- **D6. Ресурсы.** Строки и звуки — оверлеями `src/main/lang-overlays/<фича>/` и `src/main/sound-overlays/<фича>.json`; общие файлы напрямую не править. Дубль sound event валит сборку, дубли lang-ключей не ловятся — при интеграции проверять вручную. Бинарники — `src/main/binassets/<path>.b64`. Ресурсы героя — `python3 .agents/skills/add_hero/scripts/check_hero_resources.py --hero <id>`.
- **D7. События и разрушения.** Новое мировое событие регистрирует эксклюзивность в `WorldEventConflicts` и проходит полный цикл: старт → активная фаза → конец → очистка → повторный запуск. Разрушения обязаны откатываться через `city/restore` и `/city reset`.
- **D8. falbiksheroes — мягкая зависимость.** viltrumite обязан запускаться и работать без него. Доступ — только по образцу `compat/spider`: интерфейс-мост + пустая реализация + рефлексия с проверкой, без прямых импортов в общем коде. Чужой jar не менять, закрытые ресурсы и код не копировать.
- **D9. Горячий миксин.** `PlayerEntityCoreMixin` (~1500 строк): новые хуки по возможности отдельными событиями или миксинами, а не правкой общих методов.
- **D10. Память проекта.** `.memory-bank/project.md` больше лимита MCP-пуша (64 КБ): новые записи — в тематические `.memory-bank/<тема>.md`.
