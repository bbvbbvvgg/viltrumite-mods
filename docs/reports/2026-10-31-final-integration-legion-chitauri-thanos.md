### Как делались слияния
Интегратор работал через GitHub API (прямого `git push` в среде не было). API не умеет записать merge-коммит с ручным разрешением, поэтому:
1. Чистые слияния (#101 и его обновление) — обычный merge-коммит через служебный PR в интеграционную ветку.
2. Для #99 и #98 создана вспомогательная ветка от исходного SHA (`integration/merge-helper-chitauri-20261031`, `integration/merge-helper-legion-20261031`). В ней 5 конфликтных файлов выровнены по интеграционной ветке, затем merge-коммит через служебный PR (#103, #104), и сразу за ним коммиты `fix(integration): resolve the #99/#98 merge conflicts by meaning` с ручным разрешением (обе стороны сохранены).
3. Каждое разрешение сначала выполнено и собрано локально обычным `git merge`. Дерево на GitHub после каждого шага сверено с локальным деревом побайтно (`tree` SHA совпадают).

Исходные ветки и PR #101/#99/#98 не изменялись и не закрывались. Force-push не использовался. `main` не тронут.

## 4. Найденные и исправленные проблемы совместимости
Логические конфликты, которых нет в тексте merge:
1. **Правила одновременного запуска.** `/chitauri start` не видел идущего Таноса, а `/thanos start` не видел вторжения. Исправлено: `WorldEventConflicts.othersThanInvasion` учитывает `ThanosEvent.running()`; `/thanos start [force]` отказывает во время вторжения (то же сообщение и тот же `force`, что у `/meteor start` и `/event start`). Отношение Таноса и метеоритного дождя не менялось (по дизайну оба разрешены).
2. **Колесницы и левиафаны не были `Enemy`** (солдаты и Танос — были). Из-за этого легион атаковал их только после их атаки, а Мстители Капитана не выбирали их целью сами. Теперь `ChitauriChariot` и `ChitauriLeviathan` реализуют `Enemy`.
3. **Дружественный огонь между легионом и Мстителями.** Ракеты и сплеш легиона считали чужих Мстителей «нейтральными» и задевали их; удары Мстителей наносили урон костюмам легиона без учёта PvP. Добавлен общий шов `entity/SummonOwners`: призванный союзник (костюм легиона, Мститель, Квинджет, тень Джину) отвечает за своего владельца. `LegionAllies` и `CaptainTargets` применяют к нему правила PvP/команд владельца. Свои союзники никогда не бьют друг друга.
4. Новые проверки: `FinalIntegrationCompatTest` (4 теста).

Новые контекстные комбинации между героями не добавлялись.
