# Кинематографичный бой (viltrumite 2.0 · волна 1 · сессия 22) — дизайн

Статус: в работе, ветка `wave1/22-cinematic-combat`, PR в `integration/viltrumite-2.0`.
Зона: `client/cinematic/`, `combat/feel/`, пост-эффекты.

## 1. Для игрока
Каждый удар чувствуется: короткая остановка кадра (хит-стоп), тряска по профилю удара, «кадр удара»
в стиле аниме на тяжёлых попаданиях, ударная волна, которая искажает воздух. На ультимейте камера
облетает героя, появляются кинополосы, мир визуально замедляется — сцену можно пропустить одной
клавишей. Добить почти побеждённого врага можно особым вводом — короткая сцена с замедлением.
Всё это видит только тот, кто кастует (и те, кто сам включил «смотреть чужие сцены»); камеру другого
игрока никто не трогает. Есть настройки «меньше движения камеры» и «без кинокамеры».

## 2. Принципы
- Сервер решает геймплей, клиент — только ощущение. Сервер никогда не замедляется и не ждёт сцену.
- Один общий механизм тряски вместо десятков локальных вызовов: `CameraShake` остаётся фасадом
  с тем же визуальным результатом, но считает его общий микшер `CameraFeel`.
- Всё — публичный API для сессий 23, 24 и новых героев (контракт `00_INDEX.md`: «22 → 23, 24 и герои»).
- Никакой новой системы анимации (A5): позы — через существующие клипы и `client/anim/`.
- Лимиты и LOD у каждого эффекта (A13), всё убирается при выходе, смене мира, смерти.

## 3. API ощущения удара (`combat/feel/`, сервер + общий код)
| Тип | Назначение |
|---|---|
| `ShakeProfile` | именованный профиль тряски: амплитуда, частота, затухание, веса pitch/yaw/roll, FOV-толчок |
| `HitWeight` | LIGHT / MEDIUM / HEAVY / CRUSHING / FINISHER → хит-стоп, профиль, кадр удара |
| `CombatFeel` | серверный фасад: `hit(attacker, target, weight)`, `shake(level, at, profile, power, range)`, `impactFrame(...)`, `shockwave(level, at, radius, strength)` |
| `FeelS2CPacket` | один пакет на событие и зрителя; только игрокам в радиусе слежения |

Клиент (`client/cinematic/feel/`):
- `CameraFeel` — микшер до 8 слоёв «травмы» (shake = trauma², плавное затухание), сумма с мягким
  лимитом; учитывает настройки и `punchShakeMultiplier`. Наследный путь `CameraShake.add/addAt/
  cinematicAt` даёт ровно тот же сигнал, что и раньше (тот же шум и затухание 0.86/тик).
- `ImpactFrame` — 1–3 кадра: инверсия-«вспышка» и радиальные линии в стиле манги, кулдаун 8 тиков.
- `ShockwaveDistortion` — экранное кольцо преломления (пост-шейдер `cinematic_shockwave`), до 4 волн,
  только в 64 блоках и в поле зрения; без шейдера — тихий отказ.
- `HitStop` (существующий) — переиспользуется: `CombatFeel.hit` шлёт его же событие.

## 4. API кинокамеры (`client/cinematic/`, запуск — `combat/feel/Cinematics`)
- Сервер: `Cinematics.play(ServerPlayer caster, ResourceLocation scene, @Nullable Entity focus)` —
  один вызов на ультимейт. Пакет получает кастующий (сцена с камерой) и наблюдатели в 48 блоках
  (камера — только если включили «смотреть чужие сцены», иначе только тряска и искажение).
- Сцена — data-файл `assets/<ns>/cinematics/<id>.json` (клиентский ресурс): кадры (shots) с путями
  камеры относительно героя (x — вправо, y — вверх, z — вперёд по взгляду в момент старта), точки
  взгляда, FOV, крен, сглаживание; кинополосы; отрезки замедления; события на тиках (профиль тряски,
  кадр удара, волна). Сессии 23/24 добавляют сцены без кода; есть и билдер `CameraPath` в коде.
- Камера — клиентский Marker (как в существующем `JinwooUltScene`), `setCameraEntity`, возврат на
  игрока при завершении, пропуске, смерти, смене мира, открытии меню, исчезновении героя.
- Визуальное замедление: часы сцены и FX идут медленнее, ближайшие сущности «держатся» через
  `HitStop`, звуки приглушаются (`SoundDuck`). Сервер не замедляется.
- Пропуск: клавиша «Пропустить сцену» (по умолчанию Backspace) с подсказкой внизу экрана.
- Если героя уже снимает собственная камера (Джину, Танос), API не перехватывает её, а
  добавляет только слой ощущений (кинополосы, волна, замедление).

## 5. Витрина — ультимейты 4 героев
Один вызов `Cinematics.play` в серверной точке старта ультимейта: Хоумлендер, Тор, Райнхард, Джину.
Точные точки входа и сцены перечислены в PR.

## 6. Добивания
- Условие: живая цель в прицеле до 4.5 блока, здоровье ≤ max(4, 20 % максимума); боссы ≤ 8 %;
  цель не в чужом добивании; PvP — только если PvP разрешён на сервере.
- Ввод: клавиша «Добивание» (по умолчанию G) — HUD-подсказка «[G] Добить», когда цель подходит.
  Клиент только предсказывает, сервер проверяет всё заново (C2S валидация).
- Сцена 1.5–2.5 с: цель удерживается, финальный урон — через обычный путь урона в кульминации.
- 2 общих: «Апперкот в небо» и «Вбить в землю»; 2 геройских — через регистрацию в `HeroDefinition`
  или реестр стилей по `HeroId` из пакета героя (без `if (hero == X)` в общем коде).

## 7. Настройки (`viltrumitecore_cinematic.json`, клиент)
- `reduceCameraMotion` — тряска ×0.35, без крена и FOV-толчков, вместо облёта — статичный общий план,
  без искажения воздуха.
- `disableCinematicCamera` — без путей камеры (остаются кинополосы и лёгкое замедление).
- `watchOthersCinematics` (по умолчанию выкл.), `impactFrames`, `flashIntensity`.
- Экран настроек — кнопка в «Специальных возможностях» и клавиша.

## 8. Сеть

`HeroRosterIntegrationTest` (A2).

## 10. Риски
- Программный рендер (Mesa) медленный: шейдер проверяется по скриншота��, FPS не репрезентативен.
- Второй клиент может не поместиться в память машины — тогда «НЕ ПРОВЕРЕНО В ИГРЕ» с причиной.
- Конфликт с собственными камерами героев — решается приоритетом «камера героя важнее».
