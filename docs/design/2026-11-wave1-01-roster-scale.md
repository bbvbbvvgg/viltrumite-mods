# Волна 1 · Сессия 01 — Масштабируемый ростер: маска действий без лимита 64

Статус: в работе (`wave1/01-roster-scale` → `integration/viltrumite-2.0`).

## Видение для игрока

Героев становится 25+, действий — 200+. Ничего не должно ломаться: подсказки доступности, перезарядки и HUD верны у каждого героя, клавиши новых героев срабатывают, сеть не тормозит. Игрок не видит эту работу — он видит, что новые герои волны просто работают.

## Что найдено (аудит до кода)

| Место | Лимит | Последствие | Решение |
|---|---|---|---|
| `HeroPublicSnapshot.availableActions` (`long`) | 64 действия | действие с ordinal ≥ 64 нельзя замаскировать отдельно; `actionMask` бросает исключение | `ActionSet` без лимита |
| `HeroInputC2SPacket` (`writeByte(ordinal)`) | 127 действий | ordinal ≥ 128 приходит на сервер отрицательным, `HeroAction.byId` → `null`, нажатие молча теряется | varint |
| `AbilityPages` 3 × 6 = 18 слотов | на героя | ограничение раскладки одного героя, не ростера | оставить, описать в контракте |
| `COOLDOWN_COUNT = 6`, `EXTRA_COOLDOWN_MAX = 32` | на героя | значения на героя, не на ростер | оставить, описать |
| `heroFlags` (`int`) | 32 бита на героя | смысл битов принадлежит герою | оставить, описать |

Сейчас в `HeroAction` 90 значений, все герои шлют маску `-1` («всё доступно»), клиентский код маску не читает. Поэтому замена безопасна для всех 14 героев.

## Механика и контракты

1. **`hero/roster/ActionSet`** — неизменяемый набор ordinal'ов `HeroAction` поверх `long[]` без верхнего лимита. Особое значение `ActionSet.ALL` («всё доступно») — прямой наследник маски `-1L`.
   - `of(HeroAction...)`, `ofOrdinals(int...)`, `contains(HeroAction)`, `contains(int)`, `with`, `without`, `union`, `size`, `isAll`, `isEmpty`, `stream()`.
   - `fromLegacyMask(long)` / `legacyMask()` — мост к старому `long`.
   - `toBytes()` / `fromBytes(byte[])` — компактное кодирование: тег + varint. Плотная форма (битовый набор) или разреженная (дельты индексов) — выбирается более короткая.
   - `toWire()` / `fromWire(String)` — токен для строкового снимка: `-1` = ALL, `~<base64url>` = набор, десятичный `long` принимается как старый формат.
2. **`HeroPublicSnapshot`**: компонент `long availableActions` заменён на `ActionSet actions`.
   - Совместимость по исходникам: все прежние конструкторы (включая 23-аргументный с `long`) сохранены; `long availableActions()` сохранён как метод (ALL → `-1L`, иначе младшие 64 бита); `actionAvailable(HeroAction)` теперь точен для любого ordinal.
   - Новое рядом: `actions()`, `actionAvailable(int)`, `withActions(ActionSet)`, `static ActionSet actions(HeroAction...)`.
   - `actionMask(HeroAction...)` (`long`) помечен `@Deprecated`: физически не вмещает ordinal ≥ 64 — сообщение ошибки ведёт к `HeroPublicSnapshot.actions(...)`.
3. **Сеть:** снимок остаётся одной синхронизируемой строкой (атомарный вид для всех трекеров). Поле 20 — токен `ActionSet.toWire()`. `HeroInputC2SPacket` — varint вместо байта. `PROTOCOL_VERSION` 31 → 32.
4. **Сохранения:** снимок не сохраняется в NBT (только синхронизируется), поэтому миграция мира не нужна. Декодер всё равно принимает старый десятичный формат.

## План срезов

1. Ядро: `ActionSet`, снимок, кодирование, varint во входном пакете, протокол 32, тесты (256 синтетических действий, туда-обратно, границы 63/64/127/128, старый формат). Пуш без `[skip ci]` — оркестратор интегрирует первым.
2. Контракт `docs/architecture/hero-roster-scale.md`, память `.memory-bank/wave1-01-roster-scale.md`, обновление навыка `add_hero`.
3. `/hero debug actions` — отладочный вывод доступности действий, перезарядок и раскладки текущего героя (ru/en через оверлей).
4. Микробенчмарк построения и кодирования снимка (до/после) в тестах.
5. Плейтест: dedicated server + клиент, переключение всех 14 героев, HUD, перезарядки, вход второго игрока посреди способности.

## Риски

- Параллельные сессии пишут код против текущего API → сохраняю все сигнатуры, только добавляю.
- Конфликт номера `PROTOCOL_VERSION` с соседями → нормально, финальный номер назначит оркестратор.
- Размер снимка: ALL кодируется так же (`-1`), набор из 10 действий при 256 ordinal'ах — ~16 символов вместо 20 у десятичного `long`.
