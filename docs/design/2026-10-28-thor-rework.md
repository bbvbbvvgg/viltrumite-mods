# Тор: переработка после плейтеста (rework spec)

> Дата: 2026-10-28. Источник: плейтест пользователя (core 1.49.1) и аудит. Статус: утверждено пользователем, реализация по этапам.
> Дополняет `2026-10-27-thor-design.md`. Где этот документ противоречит старому — побеждает этот. Механики (маршрутизация, решения №1–220) не меняются, кроме явно названного здесь.

## 0. Вердикт плейтеста
Анимации посредственные (руки проходят сквозь тело, неверные позы), подъём Мьёльнира абсурден, молнии слабые, всё слишком быстрое (ульта «за секунду»), звук плохой, боёвка без красивых комбо. Мьёльнир (модель) — лучшая часть, его сохранить.

Корневые причины (аудит кода):
1. Тор = ванильное тело игрока (6 коробок, без локтей и кистей) + углы Эйлера, вбитые в `ThorClips`/`ThorCombatClips`/`ThorFirstPerson`. Хват руками физически невозможен.
2. Тайминги: DRAW 10 т (0.5 с), удар комбо 16 т, WRATH 52 т (удар ~24 т). Тяжести нет.
3. Звук: ни одного своего звука, только ванильные `SoundEvents`.

Эталон качества: Рейнхард (`client/reinhard/*`): собственное geo-тело 15 костей (forearm, shin, hand, grip), клипы Blockbench JSON (`reid_draw` 6 с, 12 костей, ~700 ключей), `ReinhardLayers`/`ReinhardPlayback`/`ReinhardGrip`, `ReinhardFirstPerson`.

Правило проекта остаётся: только существующая система анимаций и VFX (`AGENTS.md` §3, `.agents/skills/animation-system`). Никаких GeckoLib-анимаций, PlayerAnimator и т. п.

## 1. Тело и масштаб
- Тор получает собственное geo-тело по пути Рейнхарда (`ThorRenderer`, полный рендер вместо ванильной модели). Кости минимум: head, body, right_arm/left_arm, right_forearm/left_forearm, right_hand/left_hand, right_leg/left_leg, right_shin/left_shin, mjolnir_grip (в правой кисти), mjolnir_belt, beard, belly.
- Пропорции GoW Ragnarök: массивный, широкий торс и плечи, толстые руки, живот, борода. Рост визуально **3.2 блока** (допуск 3.0–3.5), ширина плеч заметно больше ванильной.
- Скин/текстуры: из существующих ассетов Тора (скин 64×64, борода, живот), перенесённые на новое тело; при необходимости — новая текстура тела в стиле мода. Мьёльнир — существующая модель без изменений.
- **Хитбокс тоже растёт**: высота ~3.0–3.2, ширина ~1.0–1.2, eye height пропорционально. Через `EntityEvent.Size`/`refreshDimensions` для игрока-Тора; возврат к ванили при выходе из героя, смерти, релоге, смене измерения. Проверить: позы (crouch/swim/sleep/fall-flying), подъём в 2-блочных проходах (вылет из блоков запрещён), камера, reach, ногой не застревать.
- Рендер владеет всем, что рисовала ваниль (см. animation-system §6): предмет в руке, ник, невидимость, свечение, броня/слои, shadow pass.
- **Реализовано в R1**: скелет, пивоты, якоря, конвейер позы и правила записи клипов — `2026-10-28-thor-skeleton.md` (контракт для R2). Отклонение: ширина хитбокса 0.96 (Тор проходит в 1-блочные двери).

## 2. Первое лицо
- Свои FP-руки нового тела (как `ReinhardFirstPerson`): массивные предплечья и кисти, реальные якоря кистей, Мьёльнир на кости хвата. Одни часы действия для FP и TP.

## 3. Анимации (Blockbench JSON на новом теле)
Все клипы переносятся из кода в `assets/viltrumitecore/animations/thor/thor.animation.json`. Числа-позы в Java удаляются (кроме служебного смешивания/IK).
Общие правила:
- Тяжесть: длинная подготовка, короткий контакт, долгое восстановление; вес молота ведёт руку (просадка, инерция, перехлёст). Корпус и ноги участвуют в каждом ударе.
- Никаких проходов рук/молота сквозь тело: проверка покадрово (preview) и расчётом пересечений.
- Каждая атака — одна строка данных (хитбокс, клип, FP, трейл, звук, VFX), как `hero/reinhard/melee/MeleeMoves`.

Ключевые клипы:
- **idle / walk / run / stance с молотом и без**: тяжёлая походка, молот в руке покачивается.
- **Подъём Мьёльнира из земли** (кто угодно, 1-е и 3-е лицо): присед → обе ладони на рукояти (IK к якорю рукояти) → корпус немного приподнимается, спина и руки напряжены → дрожь, попытки поднять. Для Тора — рывок и вынос молота. Руки ДОЛЖНЫ быть на рукояти в обоих видах.
- **DRAW / HOLSTER**: 1.5–2 с, молот с пояса в руку с весом (просадка руки, выравнивание).
- **Комбо молотом**: 3–4 удара с разными траекториями (горизонтальный, диагональ сверху, апперкот, финишер-удар в землю), каждый 1.2–1.5 с. **Комбо кулаками**: 3 удара, тяжёлые, 0.9–1.1 с.
- **Бросок / ловля / притягивание**: замах всем корпусом, ловля с отдачей в тело.
- **Электро-режим и электро-комбо, волна, гроза**: разряды по рукам/молоту, позы с поднятым молотом.
- **Ульта (WRATH)**: 5–7 с — подъём молота к небу, нарастание бури, удар, долгий хвост. Удар не раньше ~3 с.
- **Полёт**: рука с молотом вытянута, почти неподвижна, мелкими движениями кисти «подталкивает» вращение; тело в полёте.

## 4. Тайминги (сервер)
Новые длины фаз приёмов задаются на сервере и совпадают с клипами (тест). Ориентиры: DRAW/HOLSTER 30–40 т; удар комбо молотом 24–30 т; кулаками 18–22 т; HAMMER_STRIKE ~30 т; WRATH 100–140 т, контакт ≥ 60 т. Кулдауны/урон не меняются без отдельного решения, кроме пропорционального пересчёта окон комбо.

## 5. Полёт и раскрутка
- **Без Мьёльнира в руке Тор не летает вообще**: ни CRUISE/SONIC, ни HOVER, ни рывков в воздухе. Если молот покидает руку в полёте — Тор падает (обычное падение, без урона-исключений). Рывок двойным WASD на земле остаётся.
- Раскрутка молота перед/во время полёта: молот вращается как лопасти вертолёта, **5–8 об/с** (сейчас ~1), с размытием (motion-blur копии/трейл) и гулом; рука почти неподвижна, только кисть.

## 6. Мьёльнир в мире
- В покое молот **стоит вертикально**: боёк в земле (утоплен ~0.2–0.3 блока), рукоять вверх. Вокруг — трещины/вдавленность (декаль или частицы, без изменения блоков). Падение: молот прилетает бойком вниз и втыкается.
- Якорь рукояти для подъёма — верх рукояти (API для анимации подъёма).

## 7. VFX
- Молнии: слоями — яркое бело-голубое ядро, широкое свечение, ветвления, вспышка неба/освещения вокруг, разряды, ползущие по земле, след гари (декаль), остаточное мерцание. Толщина и длительность соразмерны масштабу Тора.
- Заряд: дуги по рукам и молоту, искры с бойка. Удары: пыль, обломки, ударная волна, хит-стоп и тряска камеры на контакте (`HeroFx`, `CameraShake`).
- Только существующий конвейер (`HeroImpactFx`, `PixelVfx`, `CameraShake`, `FlashOverlay`, `dash_impact`).

## 8. Звук (по `.agents/skills/sound-design`, PR #45)
- Cue-лист на каждый приём: замах, контакт, хвост, лупы (раскрутка, полёт, электро-режим) с остановкой.
- Слои: гром = треск + удар + долгий раскат; удар молотом = металл + земля + бас.
- Только CC0 или свои звуки, источники в `tools/assets/thor_sources.md` и `CREDITS.md`. Все вызовы через фасад `ThorSounds` (одно место для звуков), ванильные `SoundEvents` у Тора убрать.
- Сделано в R5 (заметки: `.memory-bank/sound.md`): cue-лист со стабильными id (`ThorCue`) и таблица событий — в `tools/assets/thor_sources.md`; удар из таблицы атак получает звук через `ThorCue.windup/hit/ground/tail(ThorStrike)`.

## 10. Приёмка
- Код/тесты: длины клипов = серверные длины, контактные тики, хитбокс туда-обратно, ничего не пересекается (скан мешей), `./gradlew build` зелёный (кроме известного `RegulusVisualContractTest` на arm64).
- Покадровые превью (`tools/preview_*`): каждый клип — контакт-лист спереди/сбоку/сзади + FP.
- В игре (sandbox llvmpipe ~5 FPS, xdotool): скриншоты ключевых поз FP/TP; финальная оценка ощущения — плейтест пользователя.

## 11. Приложение R2a: таблица атак, тайминги, схема клипов
Источник истины — `hero/thor/combat/ThorAttacks` (по образцу `hero/reinhard/melee/MeleeMoves`): одна строка на атаку = хитбокс (`ThorStrike`, числа урона/дальности не менялись), id клипа 3-го лица, id клипа 1-го лица, трейл (yaw/pitch от→до относительно взгляда на контакте), id звукового cue (R5, фасад `ThorSounds`), id VFX контакта (R4), фазы windup/contact/recovery (= intro/main/finish таймлайна).

**Как играется.** Шаг комбо стартует с огибающей приёма (`ThorCombatTimings`), в момент выбора удара `StagedTimeline.retime` даёт шагу фазы его строки. Урон — на первом тике контакта (`ENTER_MAIN`, тик = windup). Буфер следующего нажатия открыт с recovery (`cancellableFrom FINISH`), то есть ритм цепочки ≈ windup+contact, если жать заранее. Окно продолжения после конца шага: молот 10 т, кулаки 11 т (было 6 т на оба; пересчёт пропорционально средней длине шага). Кулдауны и урон не менялись.

### Маршруты комбо
- Молот: `thunder_chain` ЛЛЛЛ — горизонтальный `swing_right` → диагональ сверху `swing_backhand` → апперкот `uppercut` → финишер в землю `ground_slam`; `thunder_spin` ЛЛЛП — то же, финиш `spin`; бывший маршрут «uppercut» ЛЛП теперь `overhead` (финиш `overhead`). - Кулаки: `boxer` ЛЛЛ — `jab` → `cross` → `uppercut` (3 удара); `hook` остаётся строкой без маршрута. Остальные маршруты — по 3 удара, как были.

### Схема имён клипов
Файл один: `assets/viltrumitecore/animations/thor/thor.animation.json`. Имя = `clip` строки, клип 1-го лица = то же имя + `_fp`.
- `draw`, `holster`;
- `hammer_<удар>` для HAMMER_COMBO (`hammer_swing_right`, …);
- `fist_<удар>` для FIST_COMBO, префикс `FIST_` удара не дублируется (`FIST_UPPERCUT` → `fist_uppercut`);
- `hammer_strike_<удар>` для удара на СКМ, префикс `MMB_` снимается (`hammer_strike_blow`, `hammer_strike_finisher`);
- `electric_mode`, `electric_discharge_right` / `electric_discharge_left`, `electric_wave`, `electric_storm`;
- `wrath`.

Контракт (тест `client/thor/ThorClipContractTest`): у каждой строки есть оба клипа; `animation_length` = длина строки / 20 с (±0.0001); `loop` не `true` (`hold_on_last_frame` можно); ровно одна инструкция `"timeline"` `contact` на `windup / 20` с — тик урона сервера; одни и те же часы у TP и FP. Маркер `contact` зарезервирован: у клипов вне таблицы (idle/walk/run/stance, подъём, полёт, бросок…) его нет. Пока файла нет, проверка файла помечается пропущенной (abort с числом ожидаемых клипов), а не пройденной; сам проверяющий всегда тестируется на эталоне из таблицы и на поломках.
