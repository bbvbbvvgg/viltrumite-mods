# Тор (God of War Ragnarök): дизайн героя

> Дата: 2026-10-27. Источник: идея пользователя; ассеты — архив пользователя `GoW_Thor_Kratos_assets` (God of War HeroPack 3.0.0, SymbioteSpidey).
> Статус: фундамент и мост для сессий A/B/C реализованы. Механики — только по утверждённым решениям №1–220.

## 1. Рамки
- Фантазия: громовержец с Мьёльниром. Утверждённые механики — только из решений №1–220; см. §4.
- Фундамент + мост: выбор героя, скин, борода/живот, Мьёльнир на поясе/в руке, маршрутизация ввода, мост для сессий A/B/C (`hero/thor/bridge/`). Ни одна механика не реализована.
- Всё, что резолвится с клавиши, отказывает «<приём>: в разработке» + звук, пока сессия не зарегистрирует приём в `ThorMoves`. Заглушек с эффектом нет.
- Шасси ванильное: без кита Viltrumite, без пассивов.
- Полёт (rework 2026-10-28 §5, этап R3): общий модуль Viltrumite Flight — **только с Мьёльниром в руке** (`ThorHands.holds`: прикреплён и правая рука свободна), оригинальный полёт CRUISE/SONIC/HOVER. Без молота в руке полёта нет совсем (ни HOVER, ни рывков в воздухе); молот покинул руку в полёте (бросок, пояс, предмет в руке, сцена) → полёт сброшен, обычное падение с обычным уроном. Рывок двойным WASD на земле — всегда, в HOVER — только с молотом. Решение: `ThorMovementRules.allowsFlight`/`dashAllowed`, обе стороны через `ThorHero.allowsFlight` (политика `FlightPermissions`).
- Мьёльнир в мире (rework §6, этап R3): в покое стоит вертикально, боёк в земле на `MjolnirPose.BURY` = 0.22 блока, вокруг декаль трещин; бокс/опора/подъём по вертикальной позе (`MjolnirPose`). Якорь рукояти для анимации подъёма — `MjolnirPose.handleTop` / `client.thor.MjolnirAnchors`.
- Тики: 20 = 1 с.

## 2. Как стать героем
Кнопка «Стать Тором» на экране выбора (`/viltrumite choose` открывает его снова). `enter`: молот на поясе, обычный режим, приём сброшен, в чат — подсказка управления.

## 3. Скин и модель
- Скин 64×64: склейка `thor_layer1` + `thor_layer2` (TechnoGhosty).
- Борода и живот (FatherKhimsky) — geo на голове и теле, только 3-е лицо; живот скрыт под нагрудником.
- Мьёльнир (Szombie) — geo в двух точках: правая рука (`mjolnir_hand`) и правое бедро (`mjolnir_belt`). Масштаб 0.45 вшит в кубы, box UV → per-face UV. Текстура 512 → 256 px (лимит 64 КБ на запрос GitHub MCP). Руны светятся всегда (glow-проход).
- `MjolnirPlace`: HAND — молот в руке и правая рука пуста; BELT — иначе (предмет в руке всегда побеждает); HIDDEN — брошен (этап 3).
- Позы (3-е лицо): удержание −18°, клипы DRAW/HOLSTER в `ThorClips` на часах снапшота. Новый приём = тики на сервере + клип в `ThorClips`; `ThorPoser` не меняется.

## 4. Управление (маршрутизация, `ThorControls`)
Один резолвер на сервере (нажатие), на клиенте (перехват мыши) и в панели (серые слоты). Маршрутизация только выбирает id приёма; поведение даёт сессия, зарегистрировавшая его.

| Ввод | Клавиша | Контекст → id приёма |
|---|---|---|
| STRIKE | ЛКМ | полёт → нет; электро → ELECTRIC_COMBO; молот в руке → HAMMER_COMBO; иначе FIST_COMBO |
| STANCE | ПКМ | мостом не маршрутизируется (ваниль) |
| HAMMER | СКМ | окно захвата → GRAB; молот брошен/летит назад → RECALL; враг в 4 блоках → HAMMER_STRIKE; иначе HAMMER_THROW |
| POWER | R (слот 1) | ELECTRIC_MODE (переключение) |
| MOBILITY | Y (слот 2) | молот THROWN → HAMMER_PULL (решение №220); иначе нет |
| ULTIMATE | Z (слот 3, временный дефолт) | WRATH (внутренний id, имя не утверждено) |
| TELEPORT | V (слот 4) | TELEPORT_SELECT |

- СКМ — единственная точка решения (будущая A). Отпускание СКМ всегда доходит до приёма, выбранного при нажатии (`ThorMoveHandler.onRelease`, удержанные тики) — заряд броска только если выбран бросок.
- Мышь перехватывается, только если резолвнутый приём зарегистрирован. В фундаменте не перехватывается ничего.
- Выведены из маршрутизации (`ThorMove.retired()`, регистрация запрещена): GUARD, AIR_STRIKE, LIGHTNING_DASH, TELEPORT_STRIKE, DIVE_SLAM, LIGHTNING_CALL, GRAB_SLAM.
- FATALITY — только от смертельного удара молотом в руке по игроку/герою (событие LETHAL), не от клавиши.
- Рывок двойным WASD и небесная молния после электро-комбо — вне мост-маршрутизации (не клавиши слотов).

### 4.1 DRAW / HOLSTER (технические)
- Тайминги 4/2/4 т зарегистрированы фундаментом; молот меняет место в начале MAIN. Ни одна клавиша их не запускает; wire id 0/1 сохранены.
- Предмет взят в руку до хвата → DRAW прерван. Предмет в правой руке при молоте в руке → молот сразу на пояс.

### 4.2 Мост (`hero/thor/bridge/`, по `thor_foundation_api_contract_v4_1.md`)
- `ThorMoves.register(owner, move, ThorMoveDefinition, ThorMoveHandler)` — независимый per-move gate вместо `SHIPPED_STAGE`; один владелец на приём, retired → исключение.
- `ThorBridge`: `installHammerAccess` (A, один раз) / `hammer` → `HammerView` (по умолчанию без мирового молота), `state` → `ThorStateView`, окно захвата (бит 3), scene lock, camera lease (бит 4; сбрасываются при выходе/смерти/смене измерения/героя).
- `ThorEvents`: MELEE_HIT, LETHAL_HIT (до окончательной смерти), COMBO_END, THROW, RECALL, CATCH, HAMMER_STATE_CHANGED; дедупликация по `eventId`; фундамент ни на что не подписан и ничего не постит.
- Ближний удар СКМ = обработчик `HAMMER_STRIKE` (B); резолвер СКМ один (A).
- `/thor` — один dev-only корень (вне production, оператор): A/B/C добавляют дочерние через `ThorDevCommands.registerChild`; фикстуры фундамента — `/thor foundation ...`.

## 5. Общие системы (`hero/combat/`)
### 5.1 Поэтапные приёмы — `StagedTimeline`
- Фазы INTRO → MAIN → FINISH; фаза с 0 тиков пропускается; приём без тиков не стартует.
- Приоритет выше — прерывает ниже вне окна отмены; равный — нет. В окне (`cancellableFrom`) прерывает любой.
- Комбо: `maxSteps`; одно нажатие буферизуется до окна, в окне — сразу следующий шаг.
- Гиперброня: `resists(reason, phase)`; LIFECYCLE не сопротивляется никогда.
- Парные приёмы: без партнёра — отказ; партнёр в `controlTargetId`, одни часы — снапшот владельца.
- Снапшот: `actionId` = wire id, `actionElapsed/Length`, `variant` = фаза | шаг<<2.
### 5.2 Взаимодействие оружия — теги
- Герой публикует `CombatPresence` (id, теги, стойка, приоритет) через `HeroDefinition.combatPresence` (по умолчанию NONE).
- Теги иерархические (`weapon` совпадает с `weapon.hammer`). Правила называют только теги и стойки, симметричны; выбор: приоритет → специфичность → порядок регистрации.
- `defaults()`: clash (оружие ACTIVE × ACTIVE), block (ACTIVE × оружие GUARD), block_bare (тело ACTIVE × оружие GUARD). Особые встречи — новые правила с более глубокими тегами, не проверки пар героев.
- Мьёльнир: weapon.hammer, element.lightning, trait.divine/throwable/returning/unbreakable; кулаки: body.bare. К попаданиям не подключено (сессия, авторящая удары).

## 6. Жизненный цикл
NBT `Thor/Hammer` — только место молота (брошенный при загрузке → в руке, неизвестное → пояс). Режим и приём не сохраняются. Респаун и стирание — молот на поясе. Смена измерения/героя, выход — приём остановлен.

### 6.1 Посадка мирового Мьёльнира (R3)
| Случай | Поведение |
|---|---|
| Падение на верх полного блока | бойком вниз, втыкается: точка покоя = поверхность, боёк утоплен на 0.22, декаль трещин растёт ~5 т |
| Полублок / ковёр / снег / нестандартный блок | точка покоя = верх коллизии по оси молота (луч из центра); трещины рисуются только на клетках с верхом на той же высоте (не свисают с края) |
| Край блока | решает ось молота: над блоком — стоит на краю, над пустотой — падает дальше |
| Боковая грань в падении | молот выталкивается на полширины, горизонтальная скорость гасится, падает вдоль грани и втыкается ниже; если места нет (угол) — старое правило A-m10, затем зонд опоры роняет его |
| Вода / лава | луч без жидкостей: тонет до дна и втыкается там (огнеупорен) |
| Бросок в верх блока (земля) | втыкается вертикально (embedded + planted, рывок при возврате) |
| Бросок в стену / потолок | торчит бойком вдоль броска, как раньше (бокс 0.7×0.7) |
| Опора исчезла | зонд под бойком (0.4×0.1) пуст → FALLING |
| Припаркован (void recovery) | стоит вертикально в воздухе, трещин нет |
| Поднят / отозван | тело пропало или в полёте → декаль исчезает вместе с ним; при подъёме — облачко частиц блока, при отзыве — рывок из земли |
