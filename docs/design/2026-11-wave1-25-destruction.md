# Разрушения 2.0 — дизайн (волна 1, сессия 25)

Ветка `wave1/25-destruction` → `integration/viltrumite-2.0`. Сервер: `world/destruction/`, клиент: `client/destruction/`.
Развивает `world/collapse/` (обрушения) и `worldevent/aftermath/` (руины, пожары), не дублирует их.

## 1. Для игрока

Удар в небоскрёб: ударная волна идёт кольцом, стёкла лопаются одно за другим по мере прихода волны и осыпаются
блестящим дождём; от точки удара летят настоящие куски бетона — они кувыркаются, бьются о стены, ломают стёкла и
листву по пути, раскалываются на куски поменьше и калечат тех, в кого попали. Улицу накрывает стена пыли. Подбитое
здание стонет, сыплет пылью и стеклом, проседает и рушится с задержкой, поэтапно. После — кратер с
закопчёнными краями, горящие обломки, дым. `/city reset` возвращает всё до последнего стекла.

## 2. Что уже есть (основа, не дублировать)

| Система | Что делает | Как используем |
|---|---|---|
| `world/collapse` | журнал повреждений, анализ, режиссёр обрушения, опорные пробы, клиентские фрагменты (VBO), пыль, 12 звуковых слоёв | слушаем `CityCollapseEvent`, кормим `StructuralDamage`, добавляем фазы зрелищности |
| `worldevent/aftermath` | зоны руин: огонь, дым, стадии, сохранение | `CityAftermath.registerDamage/hint` для наших кратеров |
| `hero/HeroDestruction`, `HeroDebris`, `CarveJobs` | API разрушений героев, бросок блоков `FallingBlockEntity`, очередь работ | не меняем сигнатуры; новый API — отдельно и по желанию |
| `city/restore` + `CityJournalMixin` | каждая запись `LevelChunk.setBlockState` в арене города журналируется | все наши изменения блоков идут через `level.setBlock` → журнал (A8) |

## 3. Механики

### 3.1 Ударная волна (`Shockwave`)
Одна точка входа `Destruction.shockwave(level, center, ShockSpec)`. Фронт кольцом расходится со скоростью
`speed` блоков/тик до `radius`; каждый тик обрабатывается только оболочка между прошлым и новым радиусом
(инкрементально, бюджет блоков на тик). В оболочке:
- **стекло** (блоки и панели, лёд, цветное стекло) лопается с вероятностью, падающей с расстоянием и
  экранированием (≤ N лучей на тик);
- **хрупкое** (листва, факелы, фонари, цветы, горшки) срывается;
- **ядро** (`coreRadius`): незакреплённые блоки отрываются группами и улетают как обломки (3.3).

Авто-подключение без правок героев: `StructuralDamage.impact` (метеор-удар, падение Левиафана, тяжёлые удары),
крупные взрывы (`ExplosionEvent.Detonate`, ≥ 4 блоков) и удар обрушения о землю (`CityCollapseEvent.Impact`).

### 3.2 Стекло
Клиент получает пакет «стекло лопнуло» (позиции в пределах оболочки, сжато), рисует осколки: острые блики,
падают с вращением, цвет — по цвету стекла, звон — многослойный (ванильный звук стекла с разбросом pitch
+ задержка по расстоянию). Сервер убирает блоки через `level.setBlock` (журнал).

### 3.3 Обломки (`DebrisChunkEntity`, `viltrumitecore:debris_chunk`)
- Сущность несёт 1–8 состояний блока (кластер 2×2×2), массу, угловую скорость (синхронизация через spawn data).
- Физика: гравитация, сопротивление, кувырок. Удар о хрупкое (стекло, листья) на скорости — ломает и летит
  дальше; о твёрдое на большой скорости — раскалывается на меньшие обломки (в бюджете); на малой — оседает:
  ставит блок-щебень (если разрешено и в бюджете) или рассыпается частицами.
- Урон живым: `масса × скорость`, отбрасывание через `HeroRegistry.allowsExternalControl` (IMPULSE).
- Лимиты: ≤ `destructionDebrisMax` (160) на уровень, жизнь ≤ 240 тиков, старейшие гаснут первыми;
  дальность трекинга 6 чанков, рендер без вращения/теней дальше 64 блоков.

### 3.4 Пыль, дым, огонь — в бюджетах (A13)
- Сервер шлёт только «событие» (центр, сила, тип), частицы рождает клиент.
- Клиент: оценка живых частиц ≤ бюджета (аналог `AftermathFx`), LOD: полная ≤ 64 блоков, урезанная ≤ 160,
  дальше — ничего; «стена пыли» — кольцо, ползущее по земле от удара.
- Огонь: ≤ 24 блока огня на событие, только на воспламеняемом и подпалинах; дальше дым ведёт `aftermath`.

### 3.5 Структурная целостность (развитие обрушения)
- **Стон и предвестники:** когда кластер повреждений набрал 50–99 % порога обрушения, здание «стонет»:
  из трещин сыплется пыль, лопаются стёкла фасада, слышен треск — но не рушится.
- **Фасад при обрушении:** на `CityCollapseEvent.Started` стёкла секции лопаются волной снизу вверх в фазе
  скрипа, на `Impact` — ударная волна по земле, стена пыли, вылет обломков с краёв приземления.
- **Проседание:** в фазе скрипа секция визуально оседает и кренится, прежде чем рухнуть (клиент,
  существующая сцена `CollapseScene`; без новой системы анимаций — A5).
- Поэтапность — существующий `SupportChainPlan`; мы добавляем зрелищность к каждому этапу.

### 3.6 Кратеры и подпалины
`Destruction.crater(level, center, CraterSpec)`: чаша с рваным краем, вал выброса, подпалины по палитре
(трава → грубая земля, камень → булыжник/чернокамень, дерево → обугленное, в центре — магма для метеоров),
редкий огонь. Всё через `level.setBlock` → журнал (A8); руина — в `CityAftermath.registerDamage`.

### 3.7 API для способностей
`world/destruction/Destruction` — фасад: `shockwave`, `crater`, `debris`, `shatterGlass`. Спецификации —
записи с фабриками (`ShockSpec.punch()`, `.meteor()`, …) и `scaled(k)`. Старые `HeroDestruction`,
`HeroDebris`, `CarveJobs` не меняются: обратная совместимость полная, новые возможности — по желанию.

## 4. Контракты
- Сеть: один пакет `DestructionFxS2CPacket` в конце `CoreMessages`, `PROTOCOL_VERSION` 31 → 32
  (`HeroRosterIntegrationTest`). Номер финально назначит оркестратор (A2).
- События: `DestructionEvent.Shockwave` (Forge bus, после старта волны) — для 18/21 (угроза, репутация),
  22 (тряска камеры), без прямых зависимостей (A15).
- Конфиг (`config/viltrumitecore.json`, дописано в конец): `destructionEnabled`, `destructionDebrisMax`,
  `destructionGlassPerTick`, `destructionRubble`, `destructionFire`.
- Команды `/destruction` (op 2): `status`, `shockwave <pos> <power>`, `crater <pos> <radius>`,
  `debris <pos> <count>`, `glass <pos> <radius>`, `clear`.

## 5. Срезы
1. Каркас: пакет, конфиг, бюджеты, чистая геометрия волны/кратера, тесты.
2. Стекло и ударная волна: сервер, пакет, клиентские осколки, звук, авто-подключения.
3. Обломки-сущности: физика, раскол, урон, рендер с кувырком, лимиты.
4. Кратеры и подпалины, огонь в бюджете.
5. Обрушения 2.0: предвестники, фасад, проседание, пыль, вылет обломков.
6. Кодекс, локализация ru/en, память, плейтест, производительность.

## 6. Риски
- Машина 2 CPU / 4 ГБ, программный рендер: FPS llvmpipe — не FPS видеокарты; один клиент.
- Рост журнала города: щебень и подпалины пишутся только в бюджете.
- Пересечения: 03 (бюджеты), 22 (тряска/хит-стоп) — через события и собственные лимиты, связывает оркестратор.
